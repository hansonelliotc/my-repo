What I Did

This document would later be built upon by comparing it with document Ultroub, which proved to be much more complete. The only a few poems were in the original file and were not in Ultroub. I wrote code that tokenizes the file of poems. Each "token" is a symbol which represents a particular sound. When the file is tokenized, each word is decomposed into a sequence of symbols, essentially sounding out the word one consonant/vowel at a time. Spaces are also given a token, and new line characters are treated like two spaces. There is also a '&' token, which indicates that a section of the poem is missing. The list of tokens is given below. Each token is represented with a number. The list of tokens has undergone a number of changes; on multiple occasions two tokens were combined. Thus, certain tokens in the list below embrace the ambiguity which stems from our poor understanding of how words were really pronounced, such as the token for 'e', which does not always correspond to the same pronunciation of the letter 'e'.

We can use this tokenized file to learn about how the troubadours used sound. To do this, we will do what is called n-gram analysis. An n-gram is a sequence of n characters, and n-gram analysis involves counting the number of times a particular n-gram occurs. We can do these analyses on the set of all poems, poems by a specific author or a group of authors, or on a particular poem.

What This App Does and What I Have Yet To Do

Due to technical issues, this webpage does not directly interface with the tokenized file. When it is complete, users will be able to input an n-gram, and learn how often it is used, or how often it is used by specified poets. Additionally, users will be able to produce table such as the one below. This table describes how often different types of sounds are used in combination. (These are 2-grams.) For example, by consulting the table, we learn that a vowel follows a nasal sounds 794,515 times throughout in all of the poems in our document. (Note: The accuracy of the numbers in the table bellow has recently been called into question.) This table is derived from the entire file, but use will be able to create a table built from the works of a specific poet, a selection of poets, or a single poem. User will also be able to create tables which provide prerequisites. For example, if someone want to know about the starts of lines, they could create at a similar table with the prerequisite that the sounds described follow two consecutive spaces. Nearly all of this functionality has been implemented in C++. The next step is to integrate that code with this webpage.

There is one final thing that I would like to do but have not yet done, and more such things will likely come about before the project is complete. I would like to establish a metric which gives a numeric value to the proximity between two sounds, words, or lines, and I would like to use this metric to describe "paths" a poet takes while writing. The hope is that this sort of analysis will provide quantitative descriptions of different poets' writing styles.
